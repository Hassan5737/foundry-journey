# Day 02: Building a Vault Smart Contract

## Overview

In this session, I continued my Foundry and Solidity learning journey by starting a new smart contract from scratch, following the lesson with Omar.

The default Counter example files generated by Foundry were removed to make room for the new contract.

## What I Learned

- Creating a new Solidity smart contract.
- Using a `mapping` to associate Ethereum addresses with balances.
- Understanding the `payable` keyword for functions that receive Ether.
- Using `msg.value` to access the amount of Ether sent with a transaction.
- Using `msg.sender` to identify the caller of a function.
- Applying `require` to validate transaction input.
- Using `external` and `view` function modifiers.
- Returning the caller's balance through a getter function.

## Contract Structure

The `Vault.sol` contract currently includes:

- `balances`: A private mapping that stores balances by address.
- `deposit()`: Accepts Ether, rejects zero-value deposits, and updates the sender's balance.
- `withdraw(uint256 amount)`: Declared but not implemented yet.
- `getBalance()`: Returns the balance associated with the caller's address.
